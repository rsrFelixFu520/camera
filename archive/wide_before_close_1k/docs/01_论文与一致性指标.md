# 哪些指标真正能判断真实与仿真成像的一致性

检索日期：2026-11-23。结论是**有更直接的研究可用，尤其是 SEDD、IPD 和 CPD，但三者回答的是不同问题。** 当前项目应同时保留“成像链响应一致性”和“指定算法行为一致性”。下面的适用性判断是针对本项目的工程判断，不是论文给出的 AVS 验收标准。

## 2. 三类指标怎么选

| 你想回答的问题 | 主指标 | 必要输入 | 当前能否下真实一致性结论 |
|---|---|---|---|
| 焦距、主点、畸变、选目是否正确 | 靶点重投影 RMS/P95/max、全视野射线角误差、有效覆盖率、极线垂直误差 | 同一物理靶、明确 K/D/处理阶段、空间覆盖和外参 | 现有仿真读回可检查软件投影；独立实拍靶仍缺 |
| 明暗和颜色响应是否相同 | 灰阶响应曲线误差、非饱和块线性比、灰块色偏、色块 ΔE00 的中位/P95 | 同靶、匹配输入/曝光/白平衡、明确色彩空间 | 当前自然图不能代替受控靶 |
| 清晰度、噪声、暗角是否相同 | 多视场多距离 MTF50/MTF 曲线、overshoot、时间方差、暗/平场空间残差 | 锁定处理、暗场/平场/斜边和重复帧 | v5 模型演示可解释趋势，未完成 AVS 测量 |
| 最终显示外观是否接近 | 对齐 ROI 的 PSNR/SSIM + LPIPS 或 DISTS；分开报告几何误差 | 同内容、同视点、有效 mask；声明允许的配准 | Simple Room 和真实实验室场景不同，不能作像素验收 |
| 大量非配对图的整体风格差多大 | SEDD1/SEDD2，必要时补 KID/FID 与内容分层 | 多个独立场景、固定抽样与预处理，检查跨域适用性 | v5 有预训练 SEDD 试算，标为 DIAGNOSTIC_ONLY |
| 机器人感知算法是否受到相同影响 | IPD；无精确配对时用 CPD 思路及上下文覆盖；再报告任务绝对性能 | 固定算法、两端 GT、实例配对或上下文分层、独立测试集 | 当前缺逐实例 GT 和固定业务模型，不能编造分数 |

## 3. 建议的“相机一致性”验收结构

不要把所有项加权平均成一个可以被亮度补偿掩盖的总分。建议报告以下向量：

```text
几何       [重投影 P95 px, 视场覆盖, 极线 P95 px]
响应/颜色  [灰阶响应相对误差, 中性块色偏, 色块 ΔE00 P95]
光学/噪声  [各视场 MTF 曲线差, overshoot 差, 暗/平场时间噪声差, 暗角残差]
时间       [曝光中心误差 ms, 积分拖影差 px, 滚动形变差 px, 丢/重帧率]
外观       [配对 ROI SSIM, LPIPS/DISTS] 或 [非配对 SEDD1, SEDD2]
任务       [IPD/CPD, 上下文覆盖, 真实与仿真各自的绝对性能]
证据覆盖   [哪些已测、哪些未知、有效样本量、参数来源]
```

先在真实端锁定设置做重复采集，再建立“真实—真实”变化范围；用独立场景/曝光/距离作留出集。每项可接受差值应由任务预算或实机重复性与应用容差共同确定。没有业务容差时，报告误差和区间，保持 `NOT_EVALUATED`，不自创“行业合格线”。

对于一个有明确容差 ε 的标量差，可用预先固定的等效检验/置信区间：只有误差区间落在容许范围内，才接受该项。区间跨越边界时需要补样本；“差异检验不显著”不等于证明等效。连续视频应按独立场景/采集段 bootstrap，而不是把相邻帧当作独立样本。

## 4. IPD 与 CPD 的具体计算

IPD 以对应实例为单位。论文检测例中，每个 GT 实例取预测框的最大 IoU，然后计算真实/仿真性能的平均绝对差：

```text
IPD = mean_i |IoU_real(i) - IoU_sim(i)|
```

本项目的可执行入口 `scripts/evaluate_consistency.py ipd` 接收已配对的实例性能，明确把漏检记为 0。还报告两端平均 IoU 和两端都为 0 的比例，避免“两边都看不见、IPD 却很好”的误读。此附加诊断是工程补充。[IPD 原始算法](https://arxiv.org/html/2411.07375v1)

CPD 的关键不是直接对整个数据集算一次 IoU 分布距离，而是先为每个上下文找到真实与仿真的相似子集，再计算这些子集性能分布的 W1，汇总并报告没有覆盖的上下文。不要把任意特征最近邻加全局 W1 称作原论文复现。[CPD 方法与覆盖定义](https://arxiv.org/html/2208.01022v1)

## 5. 本次真的跑了 SEDD，而不只罗列论文

作者公开了训练好的 FeatureExtractor 和 StyleExtractor。本次固定仓库 commit、保存权重 SHA256，加载已训练权重，使用同一 embedding 管线处理项目真实裁图、六路 Simple Room 输出，并计算参数扫描中的风格距离。结果在 [SEDD 试算记录](../analysis/sedd_pilot.json)，图表在主报告中。

复现时发现一个需要显式记录的差别：论文 Gaussian kernel 的 `sigma=10` 对应 `gamma=0.005`，而公开 `metric.py` 将 sklearn RBF 的 `gamma` 设为 `10`。本次**同时输出两套 SEDD2**，不悄悄替换。SEDD1 不受这个带宽差别影响。[论文公式与实现设置](https://arxiv.org/html/2510.10203v3)、[作者 metric.py](https://github.com/Dingyi-Yao/SEDD/blob/master/metric.py)

为避免随机裁图影响，本次使用短边缩放到 512 后的五个固定 224×224 crop，每张图平均成一个 embedding；作者演示脚本使用随机 crop/flip。因此这些数值是本项目内部试算，不能与论文表格直接比较。五个 crop 没有伪装成五次独立采集。[作者推理脚本](https://github.com/Dingyi-Yao/SEDD/blob/master/visstyleemb.py)

**怎样解释：**若调 gamma 后 SEDD 变小，只能说该网络和抽样协议下风格距离变小；不能说 gamma 就是实机参数，更不能说焦距、传感器噪声和曝光时间全部一致。当前真实/仿真场景、位置不同，图像又少且强相关，全部结果保持 `DIAGNOSTIC_ONLY / NOT_EVALUATED`。

六路鱼眼输出还包含无效/黑边区域，本次 pilot 没有构造两端严格对应的有效光线 mask；裁图位置与无效区占比也可能改变风格特征。后续正式比较必须先建立处理合同和有效域，再按独立场景抽样，不能直接把本表分数用作调参验收目标。

## 6. 为什么仍然执行控制变量实验

检索结果解决了“是否存在更直接的指标”，没有解决“哪些参数造成眼前的差异”。v5 的单变量图集是后一问题的实验工具：先辨认现象和参数响应，再选择受控靶、合适指标与真实数据拟合。单变量响应不等于参数可唯一辨识：灯光、反射率、曝光和数字增益可能互相混淆；要在多个独立输入条件下联合检验。
